# WinGo audit and 80% accuracy research

Generated by `python -m app.backtesting.research` (output: `data/research_report.json`). Data: 5086 rounds.

## Verdict
**No model has a statistically significant edge, and 80% is not achievable from this data.** Every model scored between 46.7% and 52.9% on 1000 untouched consecutive rounds. Pure luck: the best of 20 coin-flip strategies reaches a median of 52.9% (95th percentile 54.5%). After correcting for 20 models tested, the smallest p-value is 0.80.

## Protocol
- Chronological split: DEV = first 3086 predictions (after 1,000 rounds of history), FINAL = last 1000 rounds, never used for selection.
- Walk-forward: each prediction comes from a model fitted only on earlier rounds (refit every 100 rounds). Features use `history[:t]` only (unit-tested).
- Model and confidence threshold chosen on DEV only. FINAL scored once.
- Bonferroni correction across all 20 strategies. Reverse accuracy is exactly 100% minus direct accuracy.

The model picked on DEV was `CumFreq(Big)`, which simply always predicts Big (the DEV majority). It scored 46.7% on FINAL and its "reverse" scored 53.3%. That reverse number is NOT a signal: the final window happened to contain more Small rounds (Bonferroni p = 0.80).

## Confidence filtering
Threshold chosen on DEV (0.01). On DEV, confident picks scored 50.6% (n=524); on FINAL 46.9% (n=207). The selected model's probabilities never get further than 0.02 from 50%, so there is no confident subset to filter.

## Randomness tests (all 5086 rounds)
- Digits 0-9 uniform: chi-square p = 0.55. Big share 50.2% (p = 0.83). Entropy 3.3208 of 3.3219 bits.
- 10x10 digit transition matrix: p = 0.49. Big/Small transitions: p = 0.70. Context orders 2-5: p = 0.66, 0.72, 0.52, 0.33.
- Autocorrelation lags 1-50: 5 nominally significant (about 2.5 expected by chance), 0 after correction. Runs test p = 0.69. Streak-length distribution p = 0.61.
- Digit mutual information at lags 1, 2, 3, 5, 10 (permutation test): p = 0.45, 0.57, 0.18, 0.79, 0.63.
- Time of day (round-of-day from period id): p = 0.67. Day-to-day Big share: p = 0.21.

With 1000 test rounds, an accuracy of about 54.4% is the smallest edge reliably detectable. 80% accuracy would be 19 standard errors above chance. Nothing like it exists here.

## Findings about the previous model and code
1. Existing engine accuracy: 49.8% over 4,986 walk-forward predictions (51.1% on the last 1,000), both indistinguishable from 50%. Reverse is the exact complement.
2. No look-ahead leakage found: features and counts use `history[:t]`, refits use only earlier rows.
3. The consensus leans Big 55% of the time while outcomes are 50.2% Big. This is harmless to accuracy but shows the averaged probabilities are not calibrated.
4. **Data labelling problem:** 5,039 of 5086 rows in the "1min" history carry game code `10005`, which the README lists as the 30-second game. Only 47 rows are `10001` (1-minute). Two regimes are mixed in one sequence, and the CSV timestamps are estimated, not real.
5. **Gaps:** 112 period-id jumps (about 536 missing rounds). Features treat rounds on either side of a gap as adjacent.
6. Duplicate code: `app/walk_forward.py` and `app/backtesting/walk_forward.py` are identical.
7. Two stale test modules (`tests/test_timing_integrity.py`, `tests/test_timing_verification.py`) import functions that no longer exist (`get_mode`, `period_id_date`) and fail at collection. `tests/test_security_stats_live.py` needs a running server on port 8099.
8. Other timer modes (30s, 3min, 5min) could not be tested: no data for them is in the upload and the live feed is not reachable from this environment.

## What was changed
Nothing in the prediction engine, because no change demonstrated value. Added: research harness (`app/backtesting/research.py`), `GET /api/research/report`, the frontend Research tab, and tests.

Reminder: even a true 50.2% would lose money, because the game pays slightly less than 2x on a win.
